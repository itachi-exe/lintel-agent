How we use Zetaris

One SQL layer over the city's records.

/* 1. pushdown: Zetaris pulls only this building */ CREATE REST SESSION TABLE lintel_hpd REQUEST( endpoint ".../wvxf-dwi5.json?$where= bbl='2028800017' AND ...") /* 2. the rest runs as Spark SQL in Zetaris */ SELECT violationid, class, novdescription FROM session.lintel_hpd ORDER BY inspectiondate DESC
Every tool query runs through Zetaris, liveself-hosted Zetaris 2.4.3, reached by a key-gated relay
Same rows as the city's own APIchecked row for row on 1520 Sedgwick Ave
Every answer says what ran"Records via Zetaris", or "direct" if Zetaris is ever down
Lintel07
What is unique

Intent is a permission, not a label.

Contract before toolsScout Intent does not just classify. Its signed contract is the allow list the agent executes against.
SQL as the explanationThe why is not a story written afterwards. It is the exact query and rows behind each claim.
Honest provenanceEvery answer says which data path and which writer ran: Zetaris or direct, Nightshift or rules.
